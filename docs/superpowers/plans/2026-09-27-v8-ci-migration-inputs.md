# Входные данные для отдельной миграции `v8-ci`

Рабочий репозиторий `F:\1C\Projects\v8-ci\` остаётся на раннере 0.5.5 до отдельного изменения и проверки. Этот файл фиксирует точки стыка, обнаруженные при переносе поправок форка на текущую линию Ингвара. Версию нового бинарника закрепить по фактическому `version` после завершения и проверки раннера.

| Стык в `v8-ci` | Текущий потребитель | Действие в отдельной миграции |
| --- | --- | --- |
| Проверка версии | `src/executor/mod.rs`, `SUPPORTED_RUNNER_VERSION`; `tests/runner_contract.rs` | Обновить диапазон/точную версию и проверить JSON `version` до запуска конвейера. Не считать совместимым бинарник только по успешному старту процесса. |
| Подготовка конфигурации | `src/runner/effective.rs`, `tests/fixtures/runner/effective/` | Перевести `builder` в `providers.push`; настроить `infobases.origin` в локальном слое и удалить общий `execution_timeout`. Проверить local/Docker пути и загрузку тем же бинарником. |
| Сборка | `src/composition.rs` (операция `v8-prepare/build`), `src/runner/compat.rs`, `tests/fixtures/runner/build-*.json` | Вызывать `push` вместо `build`, использовать нынешнюю форму `data.steps`, обновить имена шагов/диагностику только после сравнения реального ответа. При EDT проверить выбранный `source-set` и экспорт по его пути. |
| Проверка синтаксиса | `src/runner/compat.rs`, тесты контракта | Использовать единую команду `check`; исключения EDT передавать `--exception-file` с двумя полями `путь<TAB>сообщение`, без старого поиска подстрок. |
| Тесты | `src/steps/test.rs`, `tests/test_steps.rs` | Канонический ключ `--no-push` вместо `--no-build`; сохранить предметные исходы YaXUnit/Vanessa и различие отказа тестов от инфраструктуры. Внешний JUnit подключать только после итогового решения о допустимом каталоге вывода. |
| Строгий JSON | `src/runner/envelope.rs`, `src/runner/compat.rs`, `tests/fixtures/runner/*.json` | Сверить `ok`, `error.kind/code`, `data`, `warnings`, `steps`, `provider_dispatched`, отмену и неполный результат. Не распознавать текст stdout как успешный ответ. |
| Ожидание клиента | `tests/fixtures/runner/launch-*.json`, соответствующий шаг запуска | Проверить `launch --wait-for-exit`: timeout считается терминальным только после очистки; сбой очистки сохраняет отдельную причину, не превращается в обычный timeout. |
| Сборка артефакта и публикация | `src/steps/make_cf.rs`, `src/steps/publish.rs` | Сверить текущие `make`/`pull` контракты, атомарную публикацию и сохранение старого артефакта при отказе. |
| Управление процессом | `src/executor/local.rs`, `src/executor/mod.rs`, `tests/process.rs` | Сверить отмену, exit code и доставку работы; после ошибки процесса сохранять JSON-квитанцию и диагностические артефакты. |

Минимальный проверочный контур отдельной миграции: contract tests `v8-ci`, local fake-runner для каждого исхода, Docker сценарий, затем копия `F:\1C\Projects\otus_JenkinsExample_EDT\` с отдельной тестовой базой. Исходный EDT-проект и рабочий оркестратор не служат временной фикстурой для записи.
